# Vinfo Design System

이 문서는 `stitch_vinfo_apple_blue_edition` 폴더의 모든 현재 파일을 기준으로 새로 정리한 디자인 가이드입니다. 기존 `vinyl_information_hub/DESIGN.md`, `_5/code.html`, 그리고 `_1`부터 `_5`까지의 스크린샷을 함께 반영했습니다.

## Product Summary

Vinfo는 음악 감상 기록, 보관함, 장르 통계, 앨범/트랙 정보, AI 기반 비평 요약을 한곳에서 다루는 한국어 음악 정보 앱입니다. 전체 경험은 바이닐의 물성을 시각적 중심에 두되, 조작 방식은 iOS에 가까운 단순하고 즉각적인 모바일 앱으로 설계합니다.

핵심 정서는 "Quietly Premium"입니다. 화면은 밝고 넓게 비워 두며, 카드와 컨트롤은 부드러운 그림자와 옅은 경계선으로만 구분합니다. 강한 장식보다 앨범 아트, 음반 그래픽, 데이터 시각화가 자연스럽게 돋보이는 방향을 유지합니다.

## Screens

### Home

참조: `_4/screen.png`

홈은 사용자가 가장 최근 또는 가장 중요한 음악 정보를 바로 잡을 수 있는 진입 화면입니다. 상단에는 뒤로가기, 중앙 브랜드명, 설정 아이콘을 두고, 본문 첫 영역에는 큰 앨범 아트 카드와 현재 추천/감상 대상 정보를 배치합니다.

주요 CTA는 `Catch Now`처럼 큰 Apple Blue 버튼으로 처리합니다. 하단에는 최근 감상 목록을 카드형 리스트로 제공하고, 항목마다 썸네일, 곡명, 아티스트, 추가 메뉴를 포함합니다.

### Library

참조: `_3/screen.png`

보관함은 검색과 필터가 중심입니다. 큰 검색 입력창을 상단에 배치하고, `전체`, `최근`, `재즈`, `일렉트로닉` 같은 필터 칩을 그 아래에 둡니다. 목록 카드는 넓은 여백, 굵은 제목, 아티스트, 날짜, 우측 장르 태그로 구성합니다.

목록 화면에서는 앨범 아트보다 텍스트 스캔성이 더 중요합니다. 제목은 강하게, 부가 정보는 회색 계열로 낮춰 빠른 비교가 가능하게 합니다.

### Detail

참조: `_2/screen.png`

상세 화면은 앨범 아트와 AI 분석 내용을 함께 보여주는 정보 중심 화면입니다. 상단의 음반 이미지를 크게 노출하고, 곡/앨범명, 아티스트, 발매일, 장르 칩을 이어서 배치합니다.

평점 영역은 세 칸으로 나누어 `RYM 평점`, `비평가 점수`, `AI 확신도`를 비교 가능하게 보여줍니다. 이후 `비평가 요약`, `샘플링 & 감상 가이드`, 가사 원문/번역 세그먼트를 카드 단위로 나눕니다.

### Stats

참조: `_1/screen.png`

통계 화면은 사용자의 컬렉션 분석 결과를 시각화합니다. 기간 선택 세그먼트는 `30d`, `90d`, `1y` 구조를 사용하고, 선택 상태는 Apple Blue 배경으로 명확하게 표시합니다.

도넛 차트, KPI 카드, 막대그래프를 사용하되 색상은 파란색 계열을 중심으로 하고 보조 항목은 회색 톤으로 낮춥니다. 차트 카드 안의 텍스트는 큼직하고 간결해야 하며, 범례는 점, 장르명, 비율 순서로 고정합니다.

### Settings

참조: `_5/screen.png`, `_5/code.html`

설정은 작업형 서브 페이지입니다. 상단 앱바와 큰 섹션 제목을 유지하되, 하단 내비게이션은 표시하지 않는 방향이 자연스럽습니다. `_5/code.html` 역시 설정 화면에서는 Bottom Navigation을 억제한다는 주석을 포함하고 있습니다.

설정 항목은 `권한 상태`, `API 설정`, `테마 설정`, `데이터 관리` 순서로 구성합니다. API Key 입력은 옅은 회색 필드, 저장 버튼은 Apple Blue, 위험 동작은 빨간 텍스트로 구분합니다.

## Visual Language

### Color

기본 배경은 아주 밝은 청회색 `#f9f9ff` 또는 `#F7F8FA`를 사용합니다. 주요 상호작용 색상은 Apple Blue 계열이며, 현재 구현과 기존 문서에서 다음 색이 반복됩니다.

| 토큰 | 값 | 사용 |
| --- | --- | --- |
| `primary` | `#0058bc` | 버튼, 활성 아이콘, 주요 링크 |
| `primary-container` | `#0070eb` | 선택 세그먼트, 강조 버튼 |
| `surface` | `#f9f9ff` | 앱 배경 |
| `surface-container-lowest` | `#ffffff` | 카드 표면 |
| `surface-container-low` | `#f1f3fe` | 보조 카드, 활성 배경 |
| `surface-variant` | `#e0e2ed` | 입력, 세그먼트 배경 |
| `on-surface` | `#181c23` | 기본 텍스트 |
| `on-surface-variant` | `#414755` | 보조 텍스트 |
| `outline-variant` | `#c1c6d7` | 카드/필드 경계 |
| `error` | `#ba1a1a` | 위험 액션 |

파란색은 주요 행동과 현재 위치에만 사용합니다. 큰 면적의 배경 전체를 파랗게 채우기보다, 버튼, 선택 상태, 차트의 핵심 데이터에 집중해서 써야 합니다.

### Typography

기본 폰트는 `Hanken Grotesk`입니다. 한국어 UI에서도 화면 전체의 기하학적이고 현대적인 인상을 유지하기 위해 같은 계열을 유지합니다.

| 스타일 | 크기/행간 | 굵기 | 사용 |
| --- | --- | --- | --- |
| Display | 34 / 41 | 700 | 화면 주요 제목, 통계 헤드라인 |
| Title Large | 28 / 34 | 700 | 섹션 제목, 상세 타이틀 |
| Title Medium | 22 / 28 | 600 | 카드 제목, 설정 섹션 |
| Body Large | 17 / 24 | 400-600 | 주요 본문, 리스트 제목 |
| Body Medium | 15 / 20 | 400 | 설명, 보조 정보 |
| Label Medium | 13 / 18 | 500 | 입력 라벨, 메타데이터 |
| Label Small | 11 / 13 | 600 | 작은 태그, 보조 라벨 |

화면 제목과 카드 제목은 굵게 두되, 본문과 설명 텍스트는 충분한 행간을 유지합니다. 버튼 안 텍스트는 줄바꿈 없이 들어갈 수 있도록 최소 너비를 확보합니다.

### Shape, Elevation, Spacing

전체 형태는 둥글지만 과하게 장식적이지 않아야 합니다.

| 요소 | 권장값 |
| --- | --- |
| 기본 간격 단위 | 8px |
| 화면 좌우 패딩 | 20px |
| 카드 내부 패딩 | 16px-24px |
| 카드 radius | 12px-16px |
| 버튼 radius | 16px-20px |
| 칩 radius | 9999px |
| 입력 radius | 12px-16px |
| 카드 그림자 | `0 4px 12px rgba(0,0,0,.05)` |

카드는 흰색 표면, 얕은 그림자, 옅은 경계선으로 구분합니다. 카드 내부에 또 다른 장식 카드가 중첩되는 구조는 피하고, 반복 목록 또는 명확한 패널 단위에만 카드를 사용합니다.

## Navigation

앱의 기본 내비게이션은 하단 탭 3개입니다.

| 탭 | 역할 |
| --- | --- |
| 홈 | 추천/최근 감상 진입 |
| 보관함 | 저장된 음악 검색과 필터링 |
| 통계 | 장르와 감상 패턴 분석 |

상세 화면은 하단 탭을 유지해도 되지만, 설정처럼 임시 작업 성격이 강한 페이지는 하단 탭을 숨기는 것이 적합합니다. 상단 앱바는 뒤로가기, 중앙 타이틀, 설정 또는 보조 액션 아이콘 구조를 기본으로 합니다.

## Components

### Top App Bar

상단 앱바는 고정형 또는 화면 상단 고정 느낌을 유지합니다. 배경은 `surface`에 약한 블러를 섞을 수 있고, 하단에는 `outline-variant`를 낮은 투명도로 사용합니다. 아이콘은 Material Symbols 계열을 사용합니다.

### Bottom Navigation

하단 탭바는 둥근 캡슐형 흰색 컨테이너로 구성합니다. 활성 탭은 옅은 파란 배경과 파란 아이콘/라벨을 사용합니다. 비활성 탭은 회색 아이콘과 텍스트로 낮춥니다.

### Cards

카드는 앱의 주요 정보 단위입니다. 홈의 최근 감상, 보관함 목록, 상세 분석, 설정 그룹 모두 같은 표면 규칙을 공유합니다. 리스트 카드는 높이를 안정적으로 유지하고, 터치 영역은 최소 48px 이상 확보합니다.

### Buttons

기본 Primary 버튼은 Apple Blue 배경과 흰색 텍스트를 사용합니다. 큰 CTA는 화면 폭을 거의 채우며, 아이콘과 라벨을 함께 배치할 수 있습니다. Secondary 버튼은 흰색 또는 옅은 표면 배경에 파란 텍스트를 사용합니다.

### Chips and Segmented Controls

필터 칩은 pill 형태입니다. 선택 상태는 파란 배경과 흰 텍스트, 비선택 상태는 흰색 또는 옅은 회색 배경과 어두운 텍스트를 사용합니다. 세그먼트 컨트롤은 회색 트랙 위에 흰색 또는 파란 선택 캡슐을 얹는 방식으로 통일합니다.

### Forms

입력 필드는 `surface-variant` 계열 배경, 둥근 모서리, 경계선 없는 기본 상태를 사용합니다. 포커스 시 `primary` 2px ring을 표시합니다. 민감 정보 입력은 placeholder를 흐리게 처리하고, 저장 버튼은 입력 그룹의 우하단에 배치합니다.

### Data Visualization

도넛 차트와 막대그래프는 통계 화면의 핵심입니다. 주요 데이터는 파란색, 비교/잔여 데이터는 회색으로 처리합니다. 차트 주변에는 충분한 여백을 두고, 숫자와 단위를 가까이 묶어 이해 속도를 높입니다.

## Content Guidelines

UI 문구는 한국어를 기본으로 합니다. 문장은 짧고 직접적으로 작성합니다.

| 상황 | 권장 톤 |
| --- | --- |
| 버튼 | 동사 중심: `저장`, `Catch Now`, `전체보기` |
| 설명 | 필요한 이유를 한 문장으로 설명 |
| 분석 | 확신을 과장하지 않고 근거 중심으로 서술 |
| 위험 액션 | 빨간색과 명확한 동사 사용: `저장 기록 초기화` |

음악 비평 문장은 너무 마케팅적으로 쓰지 않습니다. 장르, 시대, 사운드 질감, 감상 포인트를 구체적으로 적어 사용자가 바로 이해할 수 있게 합니다.

## Implementation Notes

`_5/code.html`은 Tailwind CDN, Hanken Grotesk, Material Symbols를 사용합니다. 현재 토큰은 Tailwind `theme.extend`에 직접 들어가 있으므로, 이후 구현을 확장할 때는 색상, radius, spacing, fontSize 토큰을 별도 설정 파일로 분리하는 편이 좋습니다.

반응형 기준은 모바일 우선입니다. 스크린샷 폭은 298px부터 706px까지 다양하지만, 모든 화면이 긴 모바일 캔버스에 최적화되어 있습니다. 웹/태블릿 확장 시에도 본문 최대 폭은 화면 성격에 따라 800px 또는 1200px로 제한해 읽기 밀도를 유지합니다.

## Accessibility

- 주요 버튼과 탭의 터치 영역은 최소 48px 이상 유지합니다.
- Apple Blue 텍스트는 흰색 또는 매우 밝은 배경 위에서 충분한 대비를 확보합니다.
- 아이콘 단독 버튼은 접근성 라벨을 가져야 합니다.
- API Key 입력 필드는 실제 앱에서 마스킹, 표시/숨김 토글, 저장 성공/실패 상태를 제공해야 합니다.
- 차트는 색상만으로 의미를 전달하지 말고 범례와 수치를 함께 제공합니다.

## Design Principles

1. 음악 자산이 주인공입니다. 장식보다 앨범 아트, 음반 질감, 데이터가 먼저 보여야 합니다.
2. 파란색은 행동과 현재 상태에만 씁니다. 전체 화면의 분위기는 밝은 흰색과 회색 표면이 담당합니다.
3. 정보는 카드 단위로 짧게 끊습니다. 상세 화면처럼 내용이 많아도 한 카드가 한 가지 역할만 갖게 합니다.
4. 한국어 UI는 스캔성이 중요합니다. 제목, 보조 설명, 메타데이터의 크기와 색 대비를 명확히 나눕니다.
5. 설정과 입력 화면은 차분해야 합니다. 감성적인 그래픽보다 명확한 라벨, 안정적인 폼, 확실한 피드백을 우선합니다.
